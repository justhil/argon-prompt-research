长上下文注意力衰减与编码幻觉实测报告

Long-Context Fidelity & Coding Hallucination Report

本研究针对现代超长上下文模型在 32K 至 983K（约百万级 Token）真实多文件代码库中的注意力分配机制展开实证测绘。实验揭示：标准「大海捞针（NIAH）」词汇检索测试显著高估了模型在工程场景中的有效上下文容量。当上下文扩展越过 256K 临界阈值后，旋转位置编码（RoPE）高频分量衰减与 Softmax 注意力熵增共同引发「中段注意力塌陷」，导致跨模块类型解析失效，并诱发隐蔽的合成型编码幻觉（Synthesized API Hallucination）——即模型基于局部命名惯例捏造看似合理但实际并不存在的函数签名与结构体字段。

FINDING 01 / CRITICAL INFLECTION
256K Tokens 衰减拐点

隐式依赖图谱断裂

在 32K–128K 区间内，跨文件符号检索保持 >94% 的高保真度；一旦上下文越过 256K，模型对多跳类型传导（Multi-hop Type Resolution）的召回率出现非线性滑坡，至 983K 时跌至 58.9%。

FINDING 02 / HALLUCINATION SHIFT
29.8% @ 983K 编码幻觉率

注意力深度盲区（45%–75%）

编码幻觉并非均匀分布。当目标接口定义位于上下文相对深度 45%–75% 扇区时，注意力权重均值较首尾两端下降 62%，模型倾向于拼凑邻近文件的前缀与旧版参数列表，生成无法通过编译的伪造调用。

FINDING 03 / MITIGATION EFFICACY
-19.6 pp 幻觉绝对降幅

签名锚定与验证链干预

单纯依赖「两阶段先引述后生成」仅能缓解浅层遗忘；结合前置 AST 符号表索引与反事实校验（Intervention P3），可在 983K 极限长度下将编码幻觉率从 29.8% 压制至 10.2%，恢复至接近 128K 基准水平。

01. 评估语料构建 (Corpus Construction)

选取 25 个真实工业级 Rust / TypeScript / Python 多模块工程，剥离训练集中公开的知名库名称并进行一致化符号混淆（Identifier Obfuscation），彻底排除模型预训练参数记忆干扰。

02. 编码幻觉严格判定 (Hallucination Taxonomy)

通过静态语法树分析器（Tree-sitter + 编译器类型检查）自动捕获三类幻觉：(a) 调用上下文中不存在的方法名；(b) 捏造不存在的关键字参数或配置项；(c) 跨文件结构体字段类型臆测。

03. 统计显著性说明 (Statistical Rigor)

每个上下文尺度包含 250 个独立重构任务（总计 N=1,250），每个目标声明被循环置换至 10 个等距深度区间（0%–100%）进行正交测试，表格数据置信区间为 95% Bootstrap CI (±1.2%)。
